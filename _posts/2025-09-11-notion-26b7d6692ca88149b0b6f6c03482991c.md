### 일별 리더보드 도입

KEY: daily-score:<날짜> 

```bash

 3) "player:24"
 4) "357"
 5) "player:143"
 6) "199"
 7) "player:101"
 8) "45"
 9) "player:286"
10) "28"
```

오늘의 상위 스코어 세 명의 유저만 출력

```bash
ZREVRANGE daily-score:250908 0 2 WITHSCORES
1) "player:234"
2) "400"
3) "player:24"
4) "357"
5) "player:143"
```

### 데이터 업데이트

**ZADD 데이터 업데이트**

```bash
# 이미 존재하기 때문에 0 반환
ZADD daily-score:250908 200 player:286
(integer) 0

ZRANGE daily-score:250908 200 200 BYSCORE WITHSCORES
1) "player:286"
2) "200"
```

**ZINCRBY 이용해서 스코어 증감**

```bash
# ZINCRBY 통한 스코어 감소
ZINCRBY daily-score:250908 -150 player:286
"50"

ZRANGE daily-score:250908 50 50 BYSCORE WITHSCORES
1) "player:286"
2) "50"
```

관계형 데이터베이스만 이용해 실시간 차트 서비스를 구현하는 것은 까다로운 작업

모든 유저의 변경 데이터는 실시간으로 업데이트, 점수별로 데이터를 정렬해서 가져오는 작업 자체가 데이터베이스에 부하

### 랭킹 합산 

주간 리더보드는 매주 월요일마다 초기화된다고 가정 25년 09월 10일은 수요일, 따라서 이날의 주간 리더보드를 확인하면 8일, 9일, 10일까지의 스코어를 모두 합산한 값일 것이다.

관계형 데이터베이스에서 이런 주간 누적 랭킹을 구하려면 하나의 테이블에서 일자에 해당하는 데이터를 모두 가져온 뒤 GROUP BY를 통해서 선수별로 합치고, 이를 다시 소팅(using filesort)하는 작업이 필요하다. 

**레디스에서는 ZUNIONSTORE 커맨드를 사용해 간단하게 구현**

**ZUNIONSTORE?**

```bash
ZUNIONSTORE <생성할 키 이름> <합산할 키 개수> <합산할 키 ... >
```

지정한 키에 연결된 각 아이템의 스코어를 합산하는 커맨드

해당하는 일자의 키를 지정하기만 한다면 손쉽게 주간 리더보드 데이터를 얻을 수 있다.

**데이터**

```bash
# daily-score:250908 25년 9월 8일
ZADD daily-score:250908 50 player:101 250 player:24

# daily-score:250909 25년 9월 9일
ZADD daily-score:250909 200 player:286 350 player:24 400 player:234

# daily-score:250910 25년 9월 10일 
ZADD daily-score:250910 50 player:24 100 player:101 250 player:234
```

**주간 리더보드 데이터 생성**

```bash
ZUNIONSTORE weekly-score:2509-2 3 daily-score:250908 daily-score:250909 daily-score:250910
(integer) 4

ZREVRANGE weekly-score:2509-2 0 -1 WITHSCORES
1) "player:24"
2) "650"
3) "player:234"
4) "650"
5) "player:286"
6) "200"
7) "player:101"
8) "150"
```

**ZUNIONSTORE + WEIGHTS 옵션 스코어 가중치 주기**

ZUNIONSTORE 이용해 데이터를 합칠 때 스코어에 가중치를 줄 수도 있다.

만약 25년 9월 9일에 두 배 이벤트가 있었다면 9월 9일 데이터에만 가중치를 두 배로 늘려 계산할 수 있다.

```bash
ZUNIONSTORE weekly-score:2509-2 3 daily-score:250908 daily-score:250909 daily-score:250910 WEIGHTS 1 2 1
(integer) 4

ZREVRANGE weekly-score:2509-2 0 -1 WITHSCORES
1) "player:234"
2) "1050"
3) "player:24"
4) "1000"
5) "player:286"
6) "400"
7) "player:101"
8) "150"
```

# Sorted set을 이용한 최근 검색 기록

**목표:** 쇼핑몰에서 사용자가 최근에 검색한 내역을 확인할 수 있는 기능을 추가

**요구사항**

- 유저별로 다른 키워드 노출
- 검색 내역은 중복 제거
- 가장 최근 검색한 5개의 키워드만 사용자에게 노출

**관계형 데이터베이스로 구현한다면?**

```sql
# 조회 
SELECT * FROM DISTINCT keyword WHERE user_id = 123 ORDER BY reg_date DESC LIMIT 5;
```

- 유저의 검색 마다 INSERT  (쓰기 부하)
- 유저의 검색 마다 SELECT (읽기 부하)
- 주기적으로 테이블의 데이터를 삭제하는 배치 작업이 필요 (복잡성)

**레디스 Sorted Set 활용**

키: 사용자ID / 스코어: 검색 시간 / 데이터: 검색 키워드

이후에 동일한 검색 키워드를 통해 검색해도 스코어만 업데이트


레디스 TTL은 아이템 단위가 아니라 키별로 동작한다.

즉, 직접 아이템들을 삭제해야 한다.

**상위 5개만 남기는 커맨드**


- **ZREMRANGEBYRANK**
- 인덱스 0 ~ 인덱스 - 6 까지 삭제 → 인덱스 -1, -2, -3, -4, -5 제외하고 모두 삭제
- 인덱스 -1, -2, -3, -4, -5 → 상위 5개

이를 매번 추가할 때 사용하면

```bash
ZADD + ZREMRANGEBYRANK 
```

# Set을 이용한 태그 기능

블로그에 게시글을 작성할 때 태그를 추가한다고 했을 때

관계형 데이터베이스에서 태그 기능을 사용하려면 적어도 2개의 테이블이 추가돼야 한다.

<테그 테이블, 테그-게시글 테이블>

레디스에서 set을 사용하면 굉장히 간단하게 게시물의 태그 기능을 사용할 수 있다.

```bash
SADD post:47:tags IT REDIS DataStore
3
SADD post:22:tags IT Python
2
SADD post:53:tags DataStore MySQL IT
3
```

**특정 태그를 포함한 게시물들 확인**

```bash
# 포스트에 태그 추가
SADD post:53:tags DataStore IT MySQL

# 각 태그에 추가
SADD tag:DataStore:posts 53
SADD tag:IT:posts 53
SADD tag:MySQL:posts 53

# IT 태그를 가지는 게시물 조회
SMEMBERS tag:IT:posts
22
47
53

# IT, DataStore 태그를 모두 가지는 게시물 확인
SINTER tag:IT:posts tag:DataStore:posts
53

# 게시글 53의 태그 조회
SMEMBERS post:53:tags 
DataStore
MySQL
IT
```

# 랜덤 데이터 추출

게임에서 랜덤으로 게임 유저를 매핑하거나 이벤트에 옹모한 유저를 랜덤으로 추출같은 로직을 구현하는 것을 가정

관계형 데이터베이스에서 랜덤 데이터 추출을 사용할 때 ORDER BY RAND()함수를 많이 사용한다.

해당 쿼리는 조건 절에 맞는 모든 행을 읽은 뒤, 임시 테이블에 넣어 정렬한 다음 랜덤으로 limit에 해당할 때까지 데이터를 추출한다. 굉장히 부하가 많이 가는 작업이다.

**레디스를 사용하면 O(1) 시간 복잡도로 랜덤한 데이터를 추출할 수 있다.**

**RANDOMKEY 커맨드는 레디스에 저장된 전체 키 중 하나를 무작위로 반환한다.**

**HRANDFIELD, SRANDMEMBER, ZRANDMEMBER** 각각 hash, set, sorted set에 저장된 아이템 중 랜덤한 아이템을 추출할 수 있다.

COUNT 옵션으로 원하는 개수만큼 랜덤 아이템이 반환된다. (양수는 중복 X, 음수는 중복 O)

WITHVALUES 옵션을 사용하거나, WITHSCORE 옵션을 사용하면 각각 hash, sorted set 필드에 연결된 값도 함께 반환할 수 있다.

# 레디스에서의 다양한 카운팅 방법

## 좋아요 처리하기

포털 사이트 뉴스 댓글에 좋아요를 누를 수 있는 기능을 추가한다고 가정

실시간 트래픽이 많은 사이트라면 하나의 뉴스 댓글에 좋아요가 눌리는 일은 1초에 몇만 개 이상 발생할 수 있으며, **좋아요를 누를 때마다 관계형 데이터베이스 테이블의 특정 행에서 좋아요 개수 데이터를 증가시키는 일은 데이터베이스에 직접적인 영향을 끼칠 수 있다**.

또한 하나의 유저는 같은 댓글에 한 번씩만 좋아요를 누를 수 있어야 하기 때문에 단순히 좋아요의 개수를 파악하는 것이 아닌, 어떤 유저가 어떤 댓글에 좋아요를 눌렀는지의 데이터 또한 처리할 수 있어야 한다.

```bash
# 좋아요 추가
SADD comment:like:12554 345 25 967
3
# 좋아요 추가
SADD comment:like:19967 508 167 86 816
4
# 좋아요 개수 확인
SCARD comment:like:19967
4
```
