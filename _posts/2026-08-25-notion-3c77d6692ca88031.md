**회의 주요 용어 정리**

| **용어** | **정리** |
| --- | --- |
| **산출물 (Deliverable)** | 프로젝트 수행 과정에서 작성·제출하는 문서 또는 결과물. 예: 요구사항 정의서, 설계서, WBS, 테스트 문서 등. |
| **테일러링 (Tailoring)** | 표준 방법론과 산출물을 해당 프로젝트 상황에 맞게 선택·수정·조정하는 작업. 즉, 어떤 산출물을 누가 언제 어떤 양식으로 작성할지 정하는 과정. |
| **WBS** | Work Breakdown Structure. 프로젝트 업무를 세부 작업 단위로 분해하여 일정, 담당자, 진행상태 등을 관리하는 체계. |
| **PL** | Project Leader. 특정 업무 영역이나 실무 파트를 이끌고 관리하는 역할. |
| **PM** | Project Manager. 프로젝트 전체 일정, 인력, 이슈, 고객 커뮤니케이션 등을 총괄하는 역할. |
| **PMO** | Project Management Office. 일정, 보고, 회의록, Risk, Action Item, 산출물 등 프로젝트 관리 체계를 지원·관리하는 역할. |
| **CBT** | 일반적으로 Closed Beta Test. 정식 오픈 전 제한된 사용자 또는 환경에서 시스템을 검증하는 단계. 프로젝트 내 별도 정의가 있는 경우 해당 정의를 우선 확인. |
| **Risk** | 프로젝트 일정, 품질, 범위 등에 영향을 줄 가능성이 있는 잠재적 위험요소. |
| **Risk History** | Risk의 식별 시점, 원인, 대응 내용, 상태 변화, 종료 여부 등을 지속적으로 기록·추적하는 것. |
| **Action Item** | 회의에서 결정된 후속 실행 과제. 담당자, 목표일, 진행상태를 함께 관리하는 것이 일반적. |
| **Follow-up** | 이전에 논의하거나 지시한 업무·이슈가 어떻게 진행되고 있는지 지속적으로 확인하고 후속 조치하는 것. |
| **서브 프로젝트** | 전체 프로젝트를 업무 영역, 시스템, 조직 등의 기준으로 나눈 하위 프로젝트. |
| **착수보고** | 프로젝트 초기에 수행 범위, 추진계획, 일정, 조직 및 관리방안 등을 고객에게 공식적으로 보고하는 절차. |
| **주간보고** | 주 단위로 진행 현황, 차주 계획, 이슈, Risk, Action Item 등을 공유하는 보고. |
| **월간보고** | 월 단위로 프로젝트의 전체 진행 현황과 주요 이슈 및 계획을 공유하는 보고. |
| **HR** | Human Resources. 본 회의에서는 인사 데이터 또는 인사 시스템 관련 영역을 의미. |
| **배치 (Batch)** | 정해진 시간 또는 조건에 따라 데이터를 일괄 처리하는 프로그램이나 작업. 예: 인사 데이터 정기 연계 및 반영. |
