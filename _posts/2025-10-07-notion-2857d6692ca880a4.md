## Kotlin Access Modifiers

### 1. `private` - 같은 파일/클래스 내에서만

```kotlin
// 파일: Example.kt
private class Secret {  // 이 파일 내에서만 사용 가능
    private val password = [REDACTED]  // 이 클래스 내에서만
}

class Container {
    private val data = "hidden"

    fun show() {
        println(data)
    }
}

fun test() {
    val secret = Secret()  // ✅ 같은 파일이니까 OK
    val c = Container()
    // println(c.data)     // ❌ 에러!
}
```

### 2. `internal` - 같은 모듈 내에서만 (Kotlin 고유!)

```kotlin
// module-a
internal class InternalClass {
    internal fun process() { }
}

internal val config = "settings"

// 같은 모듈의 다른 패키지에서도 사용 가능
package com.other
import InternalClass  // ✅ 같은 모듈이니까 OK

// module-b에서는
import InternalClass  // ❌ 다른 모듈이라 안 보임!
```

### 3. `protected` - 서브클래스에서만

```kotlin
open class Parent {
    protected val secret = "family secret"
    protected fun familyMethod() { }
}

class Child : Parent() {
    fun use() {
        println(secret)  // ✅ 상속받았으니 OK
        familyMethod()   // ✅ OK
    }
}

class Stranger {
    fun test() {
        val p = Parent()
        // println(p.secret)  // ❌ 에러! 상속 안 받음
    }
}
```

**Kotlin의 protected는 같은 패키지에서도 안 보임!** (Java와 다름)

### 4. `public` - (기본값!)

```kotlin
// public 생략 가능
class PublicClass {
    val data = "visible"
    fun method() { }
}

// 명시적으로 작성
public class ExplicitPublic {
    public val data = "visible"
}
```

## Java Access Modifiers

### 1. `private` - 같은 클래스 내에서만

```java
public class Example {
    private String secret = "hidden";
    private void privateMethod() { }

    public void publicMethod() {
        System.out.println(secret);  // ✅ OK
        privateMethod();  // ✅ OK
    }
}

// 다른 클래스에서
Example ex = new Example();
// ex.secret;  // ❌ 에러!
```

### 2. `(default)` - 같은 패키지 내에서만 (package-private)

```java
// 아무 키워드도 안 쓰면 default
class DefaultClass {  // package-private
    String data = "package only";
    void method() { }
}

// 같은 패키지
DefaultClass obj = new DefaultClass();  // ✅ OK

// 다른 패키지
// DefaultClass obj = new DefaultClass();  // ❌ 에러!
```

### 3. `protected` - 같은 패키지 + 서브클래스

```java
package com.example;

public class Parent {
    protected String secret = "protected";
    protected void protectedMethod() { }
}

// 같은 패키지의 다른 클래스
package com.example;
class SamePackage {
    void test() {
        Parent p = new Parent();
        p.secret;  // ✅ 같은 패키지니까 OK
        p.protectedMethod();  // ✅ OK
    }
}

// 다른 패키지의 서브클래스
package com.other;
class Child extends Parent {
    void use() {
        secret;  // ✅ 상속받았으니 OK
        protectedMethod();  // ✅ OK
    }
}
```

### 4. `public` - 어디서나

```java
public class PublicClass {
    public String data = "visible everywhere";
    public void publicMethod() { }
}

```

## 주요 차이점

### 1. 기본 접근 제한자

    - **Kotlin**: `public` (생략 가능)
    - **Java**: `(default)` = package-private

```kotlin
// Kotlin
class MyClass  // public이 기본!
```

```java
// Java
class MyClass  // package-private가 기본!
public class MyClass  // public으로 명시해야 함
```

### 2. `internal` vs `(default)`

    - **Kotlin** **`internal`**: 같은 **모듈** 내에서만
    - **Java** **`(default)`**: 같은 **패키지** 내에서만

```kotlin
// Kotlin: 모듈 기준
internal class Config  // 같은 모듈의 모든 패키지에서 OK
```

```java
// Java: 패키지 기준
class Config  // 같은 패키지에서만 OK
```

### 3. `protected`의 범위

    - **Kotlin**: 서브클래스 only(패키지 무관)
    - **Java**: 서브클래스 + 같은 패키지

```kotlin
// Kotlin
open class Parent {
    protected val x = 1
}
// 같은 패키지의 다른 클래스에서 x 접근 불가 ❌
```

```java
// Java
public class Parent {
    protected int x = 1;
}
// 같은 패키지의 다른 클래스에서 x 접근 가능 ✅
```

### 4. 최상위 선언

```kotlin
// Kotlin: 최상위에 함수/변수 선언 가능
package com.example

private fun helperFunction() { }  // 이 파일에서만
internal val config = "설정"  // 같은 모듈에서만
fun publicFunction() { }  // 어디서나
```

```java
// Java: 무조건 클래스 안에 작성해야 함
package com.example;

public class Helpers {
    private static void helperFunction() { }
    public static void publicFunction() { }
}
```

# precision & scale

```kotlin
@Column(name = "balance", nullable = false, precision = 15, scale = 2)
var balance: BigDecimal = BigDecimal.ZERO,
```

      - 데이터베이스 DECIMAL / NUMERIC 타입에서 사용하는 개념

# Kotlin Data Class 상세 설명

**자동 생성되는 메서드**

```kotlin
data class User(
    val name: String,
    val age: Int
)
-------------------------------------------------------------------------
**아래 메서드들이 자동 생성**
*1. equals() / hashCode()
2. toString()
3. copy()
4. componentN()*
```

**copy()**

불변 객체의 일부 속성만 변경한 복사본을 쉽게 만들 수 있다.

```kotlin
val user = User("Alice", 25)
val olderUser = user.copy(age = 26)  *// name은 그대로, age만 변경*

println(user)       *// User(name=Alice, age=25)*
println(olderUser)  *// User(name=Alice, age=26)*
```

**destructing(구조 분해)**

componentN() 함수들이 자동 생성되어 구조 분해가 가능하다.

```kotlin
val user = User("Alice", 25)
val (name, age) = user  *// component1(), component2() 호출*

println(name)  *// Alice*
println(age)   *// 25*
```

**Data Class 제약사항**

      1. **주 생성자에 최소 1개의 파라미터 필요**
      1. **주 생성자의 파라미터는 val 또는 var이어야 함**
      1. **abstract, open, sealed, inner 클래스가 될 수 없다**

```kotlin
// 불가능
data class Empty()  // 파라미터 없음

// 불가능
data class Wrong(name: String)  // val/var 없음

// 가능
data class Correct(val name: String)
```

# Challenge 3: Default arguments

**Q: Java에서 'foo()'의 오버로드가 여러 개 있다고 가정해 보겠습니다.**

```java
public String foo(String name, int number, boolean toUpperCase) {
    return (toUpperCase ? name.toUpperCase() : name) + number;
}

public String foo(String name, int number) {
    return foo(name, number, false);

public String foo(String name, boolean toUpperCase) {
```

**Kotlin에서는 이러한 모든 Java 오버로드를 하나의 함수로 대체할 수 있습니다.** 

**foo를 사용하는 코드가 컴파일되도록 foo 함수의 선언을 변경하세요. 기본 인수와 명명된 인수를 사용하세요.**

```kotlin
// 테스트 케이스
fun useFoo() = listOf(
        foo("a"),
        foo("b", number = 1),
        foo("c", toUpperCase = true),
        foo(name = "d", number = 2, toUpperCase = true)
)


fun foo(name: String, number: Int = 42, toUpperCase: Boolean = false): String {
       return (if(toUpperCase) name.uppercase() else name) + number
}
```

number 기본값: 42, toUpperCase 기본값: false

# Challenge 4: Triple-quoted strings

**Q: Kotlin의 다양한 문자열 리터럴과 문자열 템플릿에 대해 알아보세요.
편리한 라이브러리 함수 trimIndent와 trimMargin을 사용하면 여러 줄로 된 삼중 따옴표로 묶인 문자열을 주변 코드에 맞게 서식 지정할 수 있습니다.** 

**이 호출은 접두사 값으로 #을 사용하므로 결과 문자열에 접두사 문자가 포함되지 않습니다.**

```kotlin
const val question = "life, the universe, and everything"
const val answer = 42

val tripleQuotedString = """
    #question = "$question"
    #answer = $answer""".trimIndent()

fun main() {
    println(tripleQuotedString)
}

/* 원하는 결과
question = "life, the universe, and everything"
answer = 42
*/
```

### **trimIndent() 설명**

모든 줄에서 공통적으로 존재하는 앞쪽 공백을 자동으로 감지하여 제거

```kotlin
val text = """
    첫 번째 줄
    두 번째 줄
    세 번째 줄
""".trimIndent()

// 결과:
// 첫 번째 줄
// 두 번째 줄
// 세 번째 줄
```

### trimMargin() 설명

지정된 마진 문자(기본값: `|`)를 기준으로 그 앞의 공백을 제거하는 함수

```kotlin
val text = """
    |첫 번째 줄
    |두 번째 줄
    |세 번째 줄
""".trimMargin()

// 커스텀 마진 문자 사용
val text2 = """
    #첫 번째 줄
    #두 번째 줄
    #세 번째 줄
""".trimMargin("#")
```

### trimIndent 결과

```kotlin
val tripleQuotedString = """
    #question = "$question"
    #answer = $answer""".trimIndent()

/*
#question = "life, the universe, and everything"
#answer = 42
*/
```

앞쪽 공백을 자동제거 → “#” 제거 필요

 

### trimMargin 결과

```kotlin
val tripleQuotedString = """
    #question = "$question"
    #answer = $answer
    """.trimMargin("#")
    

/*
question = "life, the universe, and everything"
answer = 42
*/    
```

마진 문자인 “#”을 포함해서 앞쪽 공백을 제거
