# EC2 역할 부여 / 정책 생성 

### **EC2 역할 부여의 이유** 

![Notion 첨부 파일](/assets/images/notion/26b7d6692ca881fc9ec2d9d0ec3fd565.png)

- EC2가 빌드된 파일을 S3로부터 다운받아야 한다. 
따라서 EC2 또한 S3에 접근하려면 권한이 필요하다. 그 권한을 부여해주는 기능이 IAM의 역할(Role)이다. 

### 정책 생성 시작 

![Notion 첨부 파일](/assets/images/notion/26b7d6692ca88182b908c8a55a792ee9.png)

### 1단계 권한 지정 

![Notion 첨부 파일](/assets/images/notion/26b7d6692ca881bb8a1dd97d3bbba056.png)

```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Action": [
                "s3:Get*",
                "s3:List*"
            ],
            "Effect": "Allow",
            "Resource": "*"
        }
    ]
}
```

- S3에 접근하는 모든 권한을 EC2에게 주겠다.

# Code Deploy Agent 설치하기

### Code Deploy Agent?

- Code Deploy 역할 → EC2 인스턴스에게 S3에서 빌드 파일 다운받아서 배포 명령 
- Code Deploy Agent: Code Deploy 와 EC2 가운데서 소통할 수 있는 중계자 필요 

[https://docs.aws.amazon.com/ko_kr/codedeploy/latest/userguide/codedeploy-agent-operations-install-ubuntu.html](https://docs.aws.amazon.com/ko_kr/codedeploy/latest/userguide/codedeploy-agent-operations-install-ubuntu.html)

### **[Ubuntu 22.04. 기준]**

```shell
sudo apt update && \
sudo apt install -y ruby-full wget && \
cd /home/ubuntu && \
wget https://aws-codedeploy-ap-northeast-2.s3.ap-northeast-2.amazonaws.com/latest/install && \
chmod +x ./install && \
sudo ./install auto
```

### **[Code Deploy Agent가 정상적으로 실행되고 있는 지 확인]**

```shell
systemctl status codedeploy-agent
```

# Github Actions 사용자 부여

### Github Actions 사용자 부여 이유

- **Github Actions**은 **S3**에게 빌드 파일을 전달, **CodeDeploy**에게 배포 진행 명령을 내린다. 
- **S3, CodeDeploy**에 접근하려면 권한이 필요하다. 
- **CodeDeploy** → **EC2** 같은 접근은 같은 AWS 자원끼리의 접근이다. 
- **Github Actions**은 외부 자원이다**.** 그래서 **역할**이 아닌 **사용자**를 부여한다.
