# Jeus Log

한국어 개발 기록을 위한 Jekyll 기반 GitHub Pages 블로그입니다.

**블로그 바로가기: [https://jeus1998.github.io](https://jeus1998.github.io)** · **[브라우저에서 글쓰기](https://jeus1998.github.io/admin/)**

## 새 글 작성하기

블로그 글 본문 안에 편집기가 들어 있지는 않지만, 오른쪽 위 **글쓰기**에서 CMS를 열어 브라우저로 작성할 수 있습니다. 개발 도구를 설치할 필요가 없습니다.

### 블로그 페이지에서 직접 작성하기 (권장)

1. [글쓰기 화면](https://jeus1998.github.io/admin/)을 엽니다.
2. **Login with Turbo**를 눌러 로그인합니다. Decap Turbo 계정은 GitHub 계정으로 인증하도록 연결되어 있습니다.
3. 왼쪽에서 **글**을 선택하고 **새 글**을 누릅니다.
4. 제목과 게시 날짜를 입력하고 필요하면 분류, 태그, 한 줄 소개를 추가합니다.
5. 본문 필드의 **마크다운** 모드에서 `## 제목`, `- 목록`, 코드 블록 등을 직접 씁니다. 이미지를 넣을 때는 **리치 텍스트** 모드로 잠시 전환해 파일을 끌어다 놓거나 이미지 도구로 올린 뒤, **마크다운** 모드로 돌아오면 됩니다.
6. 미리보기에서 확인한 뒤 **Publish**를 누릅니다. GitHub 저장소에 커밋된 뒤 Pages가 자동 배포합니다.

CMS는 Decap Turbo **Free 플랜**으로 연결되어 사이트 1개와 소유자 1명까지 카드 등록 없이 무료로 사용할 수 있습니다. 14일 Pro 체험판은 시작하지 않았습니다. [CMS 사용 및 이미지 안내](CMS_SETUP.md)를 참고하세요.

## 카테고리와 글 검색

블로그의 [카테고리 목록](https://jeus1998.github.io/categories/)에서 글을 주제별로 둘러볼 수 있고, 카테고리 이름을 선택하면 해당 목록의 글만 표시됩니다. 새 카테고리는 CMS 왼쪽 **카테고리 → 새 카테고리**에서 추가합니다. 이름과 영문 URL 주소를 저장한 뒤 글을 쓰거나 편집할 때 카테고리 입력란에서 선택하면 됩니다.

홈 검색창에서 제목, 본문, 소개, 카테고리와 태그를 검색할 수 있습니다. 카테고리 페이지에서는 현재 카테고리에 속한 글만 검색합니다.

### GitHub 웹에서 작성

1. [블로그 저장소](https://github.com/jeus1998/jeus1998.github.io)에 접속하고 `_posts` 폴더를 엽니다.
2. **Add file → Create new file**을 선택합니다.
3. 파일 이름을 `_posts/YYYY-MM-DD-영문-주소.md` 형식으로 입력합니다. 예: `_posts/2026-11-24-spring-batch-retry.md`.
4. 아래 글 틀을 붙여 넣고 제목, 날짜, 분류, 태그, 소개와 본문을 바꿉니다.
5. 페이지 아래 **Commit changes**를 눌러 `main` 브랜치에 저장합니다. 몇 분 뒤 블로그에 반영됩니다.

````markdown
---
layout: post
title: "Spring Batch 재시도 정리"
date: 2026-11-24 20:00:00 +0900
categories: [Spring]
tags: [Java, Spring Batch, 재시도]
description: "Spring Batch에서 실패한 작업을 다시 실행하는 방법을 정리합니다."
---

## 왜 정리했나요?

여기에 글을 씁니다. 문단은 빈 줄로 나눕니다.

## 코드 예시

```java
// 코드를 여기에 붙여 넣으세요.
```

## 마무리

배운 점이나 참고 링크를 적습니다.
````

### 글 머리말 항목

- `layout: post`는 글 전용 레이아웃을 사용합니다. 그대로 둡니다.
- `title`은 글 제목입니다. 콜론(`:`)이나 특수문자가 있으면 따옴표로 감쌉니다.
- `date`는 게시 날짜와 시간입니다. 한국 시간 표기인 `+0900`을 유지하고, 미래 날짜를 넣으면 게시 전까지 목록에 나타나지 않을 수 있습니다.
- `categories`는 글 분류입니다. 예: `[Spring]`, `[Java]`, `[회고]`.
- `tags`는 관련 키워드입니다. 여러 개를 쉼표로 구분합니다.
- `description`은 홈의 글 목록에 보이는 한 줄 소개입니다.

제목과 본문은 Markdown 문법을 사용합니다. `## 소제목`, `- 목록`, `[링크 이름](https://example.com)`, 코드 블록 등을 쓸 수 있습니다. 코드 블록은 세 개의 백틱 뒤에 언어 이름을 적습니다. 예: `` ```java ``. 기존 글을 고치려면 저장소에서 해당 `.md` 파일을 열고 연필 아이콘으로 편집한 뒤 커밋하면 됩니다.

## 이미지 관리

이미지는 블로그 저장소의 `assets/images` 폴더에 보관되어 글과 함께 관리됩니다. 외부 이미지 호스팅 계정은 필요 없습니다.

CMS에서 이미지를 본문으로 드래그하면 WebP로 변환되고, 최대 가로 1600px 크기로 줄어들며, 메타데이터가 제거됩니다. 파일은 `assets/images/날짜/글주소/` 폴더에 정리됩니다. 글마다 폴더가 달라 다른 글에서 같은 이름의 파일을 올려도 경로가 겹치지 않습니다. 파일명은 URL에 맞게 정리됩니다. 같은 글 폴더에 같은 파일명을 다시 올릴 때는 CMS가 덮어쓸지 확인하므로, 별도 이미지로 보관하려면 올리기 전에 파일명을 다르게 바꿔 주세요.

GitHub에서 직접 이미지 파일을 올릴 수도 있습니다. `assets/images` 폴더에 파일을 올린 뒤 본문에 Markdown 링크를 추가합니다.

```markdown
![Spring Batch 재시도 흐름도](/assets/images/파일이름.webp)
```

대괄호 안에는 이미지 내용을 설명하는 대체 텍스트를 적습니다. 글에서 사용 중인 이미지를 삭제하거나 이름을 바꾸면 링크도 함께 수정해야 합니다.

## 배포 방식

`main` 브랜치에 커밋하면 GitHub Actions가 Jekyll로 사이트를 빌드하고 GitHub Pages에 배포합니다. [Actions 실행 내역](https://github.com/jeus1998/jeus1998.github.io/actions)에서 진행 상태를 확인할 수 있습니다.


## Study Record Notion 동기화

공개된 [Study Record](https://parallel-shrine-c64.notion.site/Study-Record-d19bec251d44498c8c53ac994966d82d)의 하위 페이지를 블로그로 가져오는 동기화 도구를 준비했습니다. 현재 공개 페이지에서 확인되는 구조는 상위 분류 19개와 그 아래 페이지 링크 118개이며, 더 깊은 하위 페이지도 있습니다. 도구는 페이지 계층을 카테고리로 보존하고 Notion 페이지 ID를 기준으로 글을 갱신합니다. Notion에 업로드된 이미지는 저장소에 복사합니다.

Notion 읽기 전용 통합을 `Study Record`에 연결하고 GitHub Actions secret `NOTION_API_KEY`를 등록한 뒤, Actions에서 기존 페이지를 하나씩 가져오면 됩니다. 가져온 글은 매시간 수정·추가·삭제를 확인하며, Notion 카테고리 계층도 블로그에 반영합니다. 단계별 사용법은 [Notion 동기화 안내](NOTION_SYNC.md)를 참고하세요. 동기화되는 글과 이미지는 공개 블로그에 게시됩니다.
